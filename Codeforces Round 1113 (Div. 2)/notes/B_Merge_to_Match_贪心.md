# B. Merge to Match

## 题目信息 (Problem Info)

* **Clist Rating**: 914
* **算法标签**：贪心、排序、构造

## 一句话题意 (One-Sentence Summary)

给定两个所有 $n+m$ 个元素互不相同的数组 $a$ 和 $b$，每次操作可将 $a$ 中的两个数 $x \le y$ 替换为一个满足 $x \le z \le y$ 的整数 $z$，判断能否经过若干次操作并重排后使数组 $a$ 变为数组 $b$。

## 关键观察/转化 (Key Observations/Transformations)

* **数量下界（$n \ge 2m$）**：由于 $n+m$ 个数字互不相同，$b$ 中的每个数都不在初始的 $a$ 中，必然至少由 $a$ 中两个数（一个严格更小、一个严格更大）合并得到，故必须满足 $n \ge 2m$。
* **多余元素可无损吸收**：只要能从 $a$ 中选出 $2m$ 个元素合成出数组 $b$，$a$ 中剩余的 $n - 2m$ 个多余元素 $x$ 都可以逐一与已合成的任意元素 $b_k$ 合并——操作允许取区间端点 $z = b_k \in [\min(x, b_k), \max(x, b_k)]$，从而在不改变 $b_k$ 的前提下消耗掉所有多余元素。
* **排序后的充要判定（`a[i] < b[i] < a[n-m+i]`）**：将 $a, b$ 升序排列后：
* **必要性**：对于 `b[i]`，前缀 `b[0..=i]` 共 $i+1$ 个元素均 $\le b[i]$，它们各自需要消耗 $a$ 中一个互不相同且严格小于自身的数，故 $a$ 中至少有 $i+1$ 个数 $< b[i]$，即第 $i+1$ 小的数满足 `a[i] < b[i]`；同理，后缀 `b[i..m-1]` 共 $m-i$ 个元素至少需要 $m-i$ 个数 $> b[i]$，即第 $m-i$ 大的数满足 `b[i] < a[n-m+i]`。
* **充分性**：当 $n \ge 2m$ 时，前缀 `a[0..m-1]` 与后缀 `a[n-m..n-1]` 下标互不重叠，直接将 `(a[i], a[n-m+i])` 配对即可合法生成每一个 `b[i]`，剩余中间元素按上一条性质吸收即可。

## 算法步骤 (Algorithm Steps)

* 若 $n < 2m$，数量不足以构造 $m$ 个新数，直接输出 `NO`。
* 将数组 $a$ 和数组 $b$ 分别按升序排序。
* 遍历 $i \in [0, m - 1]$，逐一检查是否满足 `a[i] < b[i] && b[i] < a[n - m + i]`；若存在任意位置不满足，输出 `NO`。
* 遍历结束均满足条件，输出 `YES`。

## 复杂度 (Complexity)

* **时间复杂度**：单组测试数据为 $O(n \log n + m \log m)$，瓶颈在于对数组 $a$ 和 $b$ 的排序；全局总时间复杂度为 $O(\sum n \log n + \sum m \log m)$。
* **空间复杂度**：$O(n + m)$，用于存储输入的两个数组。

## 触发信号 (Trigger Signals)

* **区间合并/中值替换操作**：每次选两个数 $x \le y$ 替换为区间 $[x, y]$ 内的任意值（含端点），既意味着生成新值需要左右“夹逼”，也意味着取端点即可像“黑洞”一样无损吞并多余元素。
* **全局元素互不相同（Distinct）**：排除了原数组直接存在目标值无需合并的边界情况，直接锁定每个目标元素严格需要至少两个原数组元素参与构造。
* **操作后允许任意重排**：说明原数组的初始位置无关紧要，应当第一时间对两个数组进行排序，转化为有序序列上的首尾极值贪心匹配问题。
