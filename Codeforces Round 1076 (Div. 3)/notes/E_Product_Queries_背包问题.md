# E. Product Queries

## 题目信息 (Problem Info)

* **Clist Rating**: 1361
* **算法标签**：动态规划、完全背包、数论（调和级数）

## 一句话题意 (One-Sentence Summary)

给定长度为 $n$、值域在 $[1, n]$ 的数组 $a$，每个元素可重复选取且至少选 $1$ 个；对每个 $i \in [1, n]$，求使所选元素乘积恰好等于 $i$ 的最少选取个数，无解输出 $-1$。

## 我的第一思路 (Initial Approach)

* **有效发现与推导**：准确将问题建模为**乘法版完全背包**；先对数组 `a` 排序去重（`sort_unstable` + `dedup`），将每个出现的 `x` 初始化为 `dp[x] = 1` 以满足“至少选一个”的约束，并通过正序枚举实现同一元素的无限次选取。
* **遇到的问题**：内层循环从 `x..=n` 逐个枚举目标值 `nxt` 并用 `nxt % x != 0` 过滤，导致时间复杂度退化为 $O(n^2)$，同时输出未做缓冲，最终提交 **TLE**。

## 关键观察/转化 (Key Observations/Transformations)

* **乘法完全背包的正序转移与 $x = 1$ 的特判**
* **证明/推导**：设 $dp[v]$ 表示乘积恰好为 $v$ 所需的最少元素个数（初始为 $\infty$）。对于去重后的每个元素 $x \in a$，单选自身即可令 $dp[x] = 1$；对于任意状态 $prev$，乘上 $x$ 得到转移 $dp[prev \cdot x] = \min(dp[prev \cdot x], dp[prev] + 1)$。当 $x \ge 2$ 时严格满足 $prev < prev \cdot x$，因此按 $prev$ 从小到大正序遍历时，$dp[prev]$ 已经包含了本轮选取任意多次 $x$ 后的最优解，正确覆盖了无限次选取的情况。当 $x = 1$ 时，$prev \cdot 1 = prev$ 不会改变乘积且只会让选取数量 $+1$（严格不优），故仅需置 $dp[1] = 1$ 后直接跳过转移。
* **去重后直接枚举倍数，复杂度由调和级数保证为 $O(n \log n)$**
* **证明/推导**：同一元素在完全背包中重复出现不产生新的转移，去重后 $a$ 中所有元素两两互异且满足 $x \in [1, n]$。对每个 $x \ge 2$，只需枚举倍数 $prev \in [2, \lfloor n/x \rfloor]$（$prev = 1$ 时对应 $nxt = x$，已有全局最优值 $1$），内层循环次数精确为 $\lfloor n/x \rfloor - 1$。总转移次数上界满足调和级数：

$$
\sum_{x \in a,\, x \ge 2} \left\lfloor \frac{n}{x} \right\rfloor \le \sum_{x=2}^{n} \frac{n}{x} = n \sum_{x=2}^{n} \frac{1}{x} = O(n \log n)

$$

相比在 $[x, n]$ 内步长为 $1$ 扫描再取模判断整除，既去除了全部无效迭代，又将昂贵的取模/除法替换为乘法。

## 算法步骤 (Algorithm Steps)

* 读入数组 $a$，对其进行排序并去重，同时初始化长度为 $n + 1$ 的 `dp` 数组为 `INF`。
* 遍历去重后的每个元素 $x$，先置 `dp[x] = 1`；若 $x == 1$ 则直接跳过当前轮转移。
* 对 $x \ge 2$，正序枚举 $prev \in [2, \lfloor n/x \rfloor]$；若 `dp[prev] != INF`，则用 `dp[prev] + 1` 更新 `dp[prev * x]` 的最小值。
* 使用带缓冲的输出流（`BufWriter`）依次输出 $i \in [1, n]$ 的答案，若 `dp[i] == INF` 则输出 `-1`。

## 复杂度 (Complexity)

* **时间复杂度**：单组 $O(n \log n)$（排序 $O(n \log n)$ + 调和级数 DP $O(n \log n)$），所有测试数据总和满足 $\sum n \le 3 \cdot 10^5$，可在时限内通过。
* **空间复杂度**：$O(n)$，用于存储输入数组和 `dp` 数组。

## 我的卡点与错误点 (My Sticking Points & Mistakes)

* **步长为 $1$ 枚举目标值再取模过滤导致 $O(n^2)$ TLE**：原代码写为 `for nxt in x..=n { if nxt % x != 0 { continue; } ... }`，即使 `continue` 跳过了转移逻辑，循环本身依然完整扫描了 $[x, n]$ 的所有整数，且未跳过 `x == 1`，最坏情况循环次数达到 $O(n^2)$ 级别并附带大量 `%` 和 `/` 运算。

## 触发信号 (Trigger Signals)

* **“元素可重复选取” + “凑出恰好为 $i$ 的乘积” + “求最少个数”**：立即识别为**乘法版完全背包**。
* **值域上界较小（$1 \le a_i, i \le n \le 3 \cdot 10^5$）且转移涉及整除/倍数关系**：条件反射想到**去重 + 枚举倍数**，利用调和级数将复杂度压到 $O(n \log n)$，避免逐项取模扫描。
